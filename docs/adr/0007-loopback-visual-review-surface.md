# ADR-0007：先实现 loopback 极简可视化审查面

- 状态：Accepted
- 日期：2026-08-07

## 背景

CLI 已可生成 `HumanDecision`，但随着补丁、验证、审查和状态证据增多，人工需要一个更易核对的可视化入口。同时 Phase 0 尚无真实身份、数据库、远程访问控制和持久事件服务，不应构建看似完整但实际不可治理的 Web 平台。

## 决定

使用 Python 标准库提供仅监听 loopback 的本地 HTTP 服务，并用原生 HTML/CSS/JavaScript 提供极简审查页。不引入 Web 或前端框架依赖。

界面通过 `ReviewSession` 消费原有 `DecisionCard`、`HumanDecision` 和 `JsonlAuditJournal`，通过提供方无关 `DecisionStore` 写入决定。CLI 和 Web 复用同一个 create-only 本地存储 adapter。

界面只支持：展示卡片/证据/风险/选项、读取当前 task 的审计历史、记录一次决定。身份必须显示为未认证；工作流决定应用、Git 合并和部署必须显示为不可用。

如果提供审计日志，`PlanReview` 或 `MergeReview` 卡片与当前状态不一致时必须同时在 session 和界面层禁用提交。POST 使用本进程随机令牌、自定义 header、严格 JSON 字段和 64 KiB 上限；服务拒绝非 loopback 绑定并发送严格 CSP 等安全响应头。

静态页面结构、样式、交互脚本、session、HTTP adapter 和决定存储必须分开，以便领域规则和界面问题能够独立测试。

## 后果

- 人工可以在浏览器中核对真实证据并生成与 CLI 相同的决定文件；
- 不增加运行时依赖或构建工具，安装包显式携带静态资源；
- 状态来自可选审计日志；没有日志时明确显示未知，不推测状态；
- 页面不是远程服务，不能暴露到局域网或互联网；
- 本地令牌是 CSRF/误提交缓解，不是身份认证；
- 决定仍需独立授权应用服务才能改变状态；
- 当前不提供多任务列表、实时 Agent 控制台、diff 内容读取或制品下载。

## 替代方案

- 只保留 CLI：暂不采用，证据数量增加后人工核对效率不足。
- 立即使用 React/Vue 和后端框架：暂缓，增加构建与依赖面但没有稳定的远程身份/状态 API。
- 终端 TUI：可作为 SSH 补充，但不如浏览器适合长证据、响应式布局和未来 diff/图像展示。
- 直接在页面应用决定：拒绝，浏览器会越过授权服务并拥有工作流状态。
- 允许 `0.0.0.0` 方便共享：拒绝，当前没有认证、TLS 或远程威胁模型。

## 退出策略

未来 Web 应用可以保留 `DecisionCard`、`HumanDecision`、`DecisionStore` 和 session 规则，替换 HTTP/静态资产 adapter。引入框架前必须先具备认证身份、持久状态 API、制品访问控制和至少一个真实测试床闭环。
