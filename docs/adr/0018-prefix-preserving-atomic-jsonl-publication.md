# ADR-0018：本地追加链以前缀保持的原子文件代发布

- 状态：Accepted
- 日期：2026-08-12

## 背景

Phase 0 的 `workflow.jsonl` 和 `records.jsonl` 都使用哈希链接记录，但此前通过一次
`os.write(..., O_APPEND)` 直接写入最终文件。操作系统不保证任意长度写入在进程
退出、磁盘错误或 partial write 时完整；尾部半条 JSON 会使整条链无法读取，也
无法可靠判断它是未提交写入还是已提交证据遭到篡改。

恢复器可以处理“某条完整记录尚未追加”，却不应通过截断权威文件来猜测半条尾部
是否可删除。引入数据库前，需要一个 Windows/POSIX 共用、无新增依赖的本地提交
原语，使进程级崩溃只暴露旧链或完整新链。

## 决定

1. `JsonlAuditJournal` 和 `LocalRunLedger` 的逻辑格式、记录哈希和 stage/state 规则
   保持不变；每次发布的新 generation 必须严格由已验证的原文件字节前缀加一条
   新记录组成。
2. append 在目标同目录创建权限受限的临时文件，循环写入完整旧 generation 和新
   记录，`fsync` 文件后使用 `os.replace` 原子发布。POSIX 额外 `fsync` 父目录；
   Windows 使用平台提供的 replace 持久化边界。
3. replace 前发生写入错误或进程退出时，权威路径仍指向旧 generation；replace
   成功后，读者只看到完整新 generation。正常异常路径删除本次临时文件；强制
   进程退出可能留下未提交临时文件，读者必须忽略它。
4. 物理文件 generation 会被替换，但逻辑审计内容只能前缀追加。所有旧记录均在
   发布前重新读取并完成 schema、序列、previous hash 和 record hash 验证，任何
   无效旧链都禁止生成新版本。
5. 本实现仍是单控制器语义；进程内锁只序列化同一 journal/ledger 实例。它不宣称
   解决多个控制器的 compare-and-swap、锁租约、事务 outbox 或权限隔离，这些仍由
   ST-02 的事务存储 adapter 承担。

## 理由

- 同目录原子替换是标准库内能同时覆盖 Windows/POSIX 且不暴露 partial JSON 的
  最小实现。
- 保持 JSONL schema 不变，现有检查、run 语料和哈希链无需迁移。
- 不自动截断权威文件，避免恢复器把真实篡改误判为可丢弃的未提交尾部。

## 后果

- workflow journal 和 run ledger 的进程崩溃可见状态收敛为完整旧链或完整新链。
- 写入成本随本地链长度线性增长；Phase 0 单任务小语料可接受，但它不是大规模
  事件存储方案。
- 强制退出可能遗留隐藏 `.tmp` 文件；它不参与读取，可由未来有证据边界的本地
  维护命令清理。
- 机器掉电和底层文件系统/硬件失效仍超出单机测试保证；生产阶段需要事务数据库、
  备份、外部锚定和恢复演练。

## 未选择的方案

- 继续直接 `O_APPEND` 并假设单次 write 原子：拒绝，记录长度不受原子写保证约束。
- 检测到无效尾部后自动 truncate：拒绝，无法在不增加提交协议的情况下证明尾部
  从未提交。
- 每条记录改为独立文件：暂不选择，会引入格式迁移、索引和跨文件枚举一致性；
  可在真实规模数据证明全文件代发布不可接受后重新评估。
