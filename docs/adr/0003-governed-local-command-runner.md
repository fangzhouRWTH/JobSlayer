# ADR-0003：受政策治理的本地命令运行器

- 状态：Accepted
- 日期：2026-08-07

## 背景

JobSlayer 已能建立任务级 Git worktree，但还不能受控地执行构建和验证命令。直接把任意 Agent 字符串交给 shell 会引入命令注入、环境密钥泄露、无限运行和输出失控等风险。

## 决定

Phase 0 新增提供方无关的 `CommandRequest`、`CommandPolicy`、`CommandRule` 和 `CommandResult`，以及本地 `GovernedCommandRunner` adapter。

运行器遵循以下规则：

- 不使用 shell，只接受参数数组；
- 请求必须匹配可信控制器提供的精确命令或参数前缀规则；
- 工作目录必须解析到已登记 worktree 内，拒绝 `..` 和逃逸 symlink；
- 不继承调用进程环境，使用最小 PATH、临时 HOME/TMPDIR 和非交互 Git 设置；
- 对 wall-clock 设置上限，超时终止整个进程组；
- 持续排空 stdout/stderr，只保留政策允许的前缀，并记录完整字节数与 SHA-256；
- 返回结构化状态、退出码、时长、截断标记和输出证据。

命令政策由可信验证配置或控制器产生，不能由 Agent 自行扩大。请求声明的 timeout 不能超过政策和匹配规则上限。

## 安全边界

本地 runner 是“受治理执行器”，不是强安全沙箱。允许 Python、编译器或测试框架意味着该进程理论上仍可访问主机网络、设备和当前用户可读文件。环境净化和工作目录约束不能提供内核级隔离。

因此本实现只用于受信仓库的早期验证命令。真实不可信 Agent 必须在后续 OCI/VM 沙箱中运行，并增加 CPU、内存、磁盘、网络和系统调用限制。

## 后果

- 验证命令必须显式登记，增加少量配置成本；
- 不同项目能用同一结构化结果生成验证证据；
- 超时和输出量可控，但 CPU/内存/网络尚未强隔离；
- 同步 API 适合 Phase 0，后续长任务需要可取消的异步执行句柄。

## 替代方案

- `shell=True` 执行 Agent 文本：拒绝，注入和审计风险过高。
- 仅按可执行文件名放行所有参数：拒绝，`python -c`、`git` 等仍可执行任意行为。
- 立即引入 Kubernetes/Dagger：暂缓，当前先验证契约、事件和证据形态。

## 退出策略

外部调用方只依赖 command 契约和 runner 协议。容器、Dagger 或远程执行器应复用相同政策匹配和 `CommandResult`，本地 adapter 可随风险提升而禁用。
