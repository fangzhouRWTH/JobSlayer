# JobSlayer 初步实施路线图

## 规划口径

路线图以“可验证的闭环能力”为单位，而不是以功能数量为单位。每个阶段只有满足退出条件才进入下一阶段；日期在团队容量明确后再承诺，优先级和依赖关系已经确定。

状态标记：`[x]` 已初步落实，`[ ]` 未落实，`[~]` 仅有骨架、尚未接入真实外部系统。

## Phase 0 — 契约与研究骨架（当前）

目标：证明外部编码执行器可以被稳定的内部契约和确定性状态机治理。

- [x] 建立仓库开发指导、架构原则和首个 ADR；
- [x] 定义 `TaskSpec`、`AgentRunSpec`、`RunEvent`；
- [x] 定义 `ArtifactManifest`、`VerificationReport`、`TransitionRecord`；
- [x] 实现合法状态转换、行为者权限和完成门禁；
- [x] 实现带序列号和哈希链校验的追加式 JSONL 审计日志；
- [x] 提供 CLI 闭环演示和自动化测试；
- [ ] 实现 Git 仓库镜像与一任务一 worktree；
- [ ] 实现受限本地命令运行器（超时、取消、输出捕获、资源限制）；
- [ ] 接入第一个 Codex CLI 适配器并保留原始事件；
- [ ] 支持从任务 JSON 创建真实运行；
- [ ] 建立一个确定性验证配置和真实样例仓库；
- [ ] 提供最小人工计划/合并审批入口。

退出条件：一个真实小问题能够从类型化任务进入隔离工作区，由 Codex 产生补丁，经确定性测试和人工审批形成可审计合并提案，全程不需要人工拼接终端步骤。

## Phase 1 — 工程 MVP

依赖：Phase 0 闭环稳定并完成至少 20 个内部样例任务复盘。

- [ ] PostgreSQL 状态存储和迁移机制；
- [ ] 上下文包选择、版本、大小预算和内容哈希；
- [ ] 制品注册表和对象存储接口；
- [ ] Dagger 构建/测试定义；
- [ ] 基于风险、错误类型和预算的有界重试；
- [ ] OpenTelemetry 统一运行层级；
- [ ] Langfuse 或 Phoenix 二选一的观测验证；
- [ ] Promptfoo 的模型/提示回归套件；
- [ ] 项目仪表板、证据面板和审批收件箱；
- [ ] OpenHands 适配器的有界 PoC。

退出条件：系统进程重启后任务状态和证据不丢失；两种执行器可在相同任务契约和验证配置下比较；使用者可在一个界面完成审批和证据查看。

## Phase 2 — 图形、仿真与训练领域验证

依赖：已有真实 C++/Python 工程任务和可重复基线。

- [ ] C++ 编译矩阵、静态分析和 sanitizer 配置；
- [ ] shader 编译、验证层、headless capture 与图像差分；
- [ ] 固定种子仿真回放、不变量和数值容差；
- [ ] 性能、内存和 VRAM 阈值；
- [ ] 训练烟雾测试、配置/数据/检查点血缘；
- [ ] 按实测成功率选择模型和执行器；
- [ ] 架构决策和任务上下文联动；
- [ ] 高风险任务的独立评审规则。

退出条件：至少一种图形或仿真任务可以用领域证据自动阻止错误补丁进入合并评审。

## Phase 3 — 持久与分布式执行

仅在出现小时/天级任务、服务重启恢复、远程 GPU 或并行训练的真实需求后引入：

- [ ] Temporal 持久工作流；
- [ ] Ray 仿真/训练任务；
- [ ] 远程 GPU worker 与硬件指纹；
- [ ] 对象存储、配额、调度和恢复；
- [ ] Kubernetes 与 Argo/Flyte 的有界评估。

退出条件：长任务可从故障中恢复，GPU/训练制品可追溯，控制平面不重复实现集群调度器。

## Phase 4 — 多项目平台

- [ ] 多仓库与跨项目依赖；
- [ ] RBAC、团队和租户隔离；
- [ ] 可复用工作流/验证模板；
- [ ] 组织级方法库和历史失败集；
- [ ] 提供方组合管理与灰度发布；
- [ ] 仅在独立 Agent 服务确有互操作需求时评估 A2A。

## 接下来三个迭代

### 迭代 A：真实工作区

1. 定义 `WorkspaceManager` 协议和工作区清单；
2. 基于固定 commit 创建/销毁 Git worktree；
3. 校验允许/禁止路径并生成 patch；
4. 测试并发任务不共享可写目录。

### 迭代 B：受限执行与 Codex

1. 定义 `AgentExecutor` 及取消语义；
2. 使用参数数组启动子进程，实施超时和进程树终止；
3. 将 Codex JSONL 输出归一化为 `RunEvent`；
4. 原始日志注册为不可变制品；
5. 在无网络、无密钥的测试配置中运行首个任务。

### 迭代 C：验证与人工门禁

1. 定义版本化 validation profile；
2. 运行 schema、lint、build 和 test 检查并生成证据哈希；
3. 将失败检查引导到一次有界修复；
4. 输出包含 diff、证据、风险和建议的决策卡；
5. 人工批准后仅生成合并提案，不自动推送或部署。

## 风险登记

| 风险 | 早期信号 | 当前缓解 |
|---|---|---|
| 框架对象侵入领域模型 | 公开 API 出现厂商类 | 适配器边界和 ADR 审查 |
| Agent 叙述被当作完成证据 | 无测试也进入完成态 | 状态机完成门禁 |
| 审计记录可被静默改写 | 历史状态无法重放 | 追加日志与哈希链 |
| 过早基础设施化 | 尚无真实任务就引入集群 | 阶段退出条件 |
| 沙箱形同虚设 | 共享目录、长期密钥、开放网络 | 一任务一工作区和最小权限设计 |
| 验证只覆盖通用 Web 任务 | GPU/仿真缺陷无法复现 | Phase 2 领域验证配置 |

说明：Phase 0 哈希链用于发现意外或局部篡改，不防御有权重写整个日志的主体。生产阶段还需要事务存储、受控写入、备份、保留策略与外部审计锚点。
